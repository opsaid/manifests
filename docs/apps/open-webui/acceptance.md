# Open WebUI 运行与发布验收

本文给出试点从本地合同检查进入目标环境验收的步骤。维护者要求暂不考虑集群验收，
当前未填入真实环境，未执行集群验收，
不能据此宣布上架。输入、部署命令和更新方式见 [接入说明](README.md)，
全局发布门槛见 [公共规范](../../spec/addon-store.md)。

## 执行前提

由部署执行方明确目标 Kubernetes context、专用 namespace、私有 overlay 路径和秘密来源。
私有 overlay 固定可访问的公共 Git tag 或完整 commit SHA；检查其内容与本次待验收包一致。
当前工作区未提交的改动不包含在已有远程 ref 中，本地构建不能代替远程 ref 验证。

准备 PostgreSQL/pgvector、S3、模型 API 和入口；启用 OIDC 时准备回调。真实配置和运行证据
留在私有或受控位置；公共记录只保存经过审查的环境版本、检查结论和必要的脱敏证据。
不用日志或普通制品传递 Secret 渲染值。

## 验收顺序与判据

| 步骤 | 操作与通过条件 | 需保留的证据 |
| --- | --- | --- |
| 1. 版本与配置 | 记录 Git ref、Kustomize/Kubernetes 版本、架构、镜像版本；依赖与必填输入通过检查 | 版本清单、脱敏输入检查结论 |
| 2. 部署前比较 | 依接入说明在受控临时副本构建，与旧入口比较对象身份、镜像、权限、配置和存储；说明每项差异 | 脱敏差异结论、备份与回退前提 |
| 3. 启动和就绪 | 经授权部署后，open-webui 和 Redis rollout 完成；探针正常，无镜像拉取、权限或缓存写入错误 | rollout/探针结论、经过审查的错误摘要 |
| 4. 核心链路 | 数据库连接和 vector 扩展可用；模型请求成功；上传文件可读取 | 各链路成功结果，不记录凭据和业务内容 |
| 5. 登录 | 启用 OIDC 时登录/回调成功，角色与分组行为符合声明；未启用则标为不适用 | 实际启用功能及结果 |
| 6. 配置更新 | 修改一个可观察且无业务破坏的非敏感输入，仅更新 ConfigMap 后不能直接判成功；滚动相关 Deployment 后确认新 Pod 使用新配置，随后恢复测试值 | 测试键名、滚动与恢复结论 |
| 7. 重建与数据 | 在测试环境分别重建应用和 Redis Pod；核对上传内容、会话及需保留的数据；记录预期丢失的缓存和已知限制 | 重建前后检查结果、数据归属 |
| 8. 升级回退准备 | 确认备份可用、数据库迁移兼容性和恢复步骤；只回退 Git ref 不视为数据回退 | 备份/恢复验证、版本兼容说明 |

步骤 7 会影响测试实例，必须确认 context、namespace 和业务窗口；不可在未确认目标的集群
执行重建。数据验证使用专门的测试数据，不以删除整个 namespace 作为卸载或数据验证手段。

## 发布交接

运行验收完成后，更新支持环境和已知限制；由维护者审查提交、CHANGELOG、catalog 登记及
不可移动版本 tag。现有 GitHub Actions 必须在目标提交上通过，公开复核和可见性条件继续
按状态文档确认。

发布候选创建后，从干净目录使用真实 URL 和固定 ref 构建完整 overlay，再核对对象及引用。
失败时修复后发布新版本，不移动旧 tag；远程复验通过后才宣布可安装。私有部署入口切换与
凭据来源也应完成验证；本地临时 env 注入不自动成为 Argo CD 持续调谐的凭据交付方案。
